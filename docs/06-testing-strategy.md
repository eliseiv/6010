# 06 — Testing Strategy

## Пирамида

```
        e2e / integration (FastAPI + реальная/тестовая БД, OpenAI замокан)
      ───────────────────────────────────────────────
     unit (services: context-builder, token-оценка, prompt, error-mapping)
```

Основная масса — unit-тесты сервисного слоя; сверху — интеграционные тесты HTTP через `httpx.ASGITransport`. OpenAI всегда замокан (`respx`/monkeypatch клиента) — реальные вызовы в тестах запрещены.

## Правило: тестирование изменений, зависящих от поведения LLM (зафиксировано — ADR-008)

Для любого изменения, чья корректность зависит от поведения LLM (например language-mirroring, формат вывода, следование инструкции), **запрещено** ограничиваться проверкой «строка присутствует в prompt»: такая проверка не ловит регрессию поведения (см. провал ADR-007 на проде). Обязательно:

1. **Детерминированная проверка серверного механизма** — то, чем сервер управляет до/вместо модели, тестируется без LLM:
   - чистые функции (например `detect_response_language`) — таблицей вход→ожидаемый результат, включая edge-кейсы (короткие, смешанные, неопределимые строки, fallback);
   - факт и содержимое инъекции в `messages[]` — собранный массив проверяется напрямую (последнее сообщение = `system` с директивой языка, содержащей правильный целевой `{language_name}`); для `translate_or_adapt` — директива отсутствует.
2. **Интеграционная проверка реального кейса** — с замоканным OpenAI assert на то, что в перехваченном запросе к OpenAI присутствует корректная директива для кейса **EN-вопрос по RU-контексту** (message на английском + транскрибация на русском → последнее system-сообщение требует ответа на English).
3. Проверка «наличие строки в системном prompt» допустима только как дополнение, не как единственная гарантия поведения.

## Уровни

| Уровень | Что покрывает | Инструменты |
|---|---|---|
| Unit | Построение контекста (summary-first, усечение), оценка токенов (tiktoken), маппинг ошибок→HTTP, извлечение structured_blocks, выбор системного prompt, **детекция языка (`detect_response_language`) и инъекция директивы языка** | pytest, pytest-asyncio |
| Integration | Endpoints `/api/transcriptions`, `/api/chat/messages`, `/api/transcriptions/{id}/messages`, `/health`; auth (X-API-Key); коды ошибок | pytest + httpx ASGITransport + тестовая Postgres |
| Contract | Соответствие request/response схемам из 02-api-contracts | pytest (валидация Pydantic) |

## Тестовая БД

- Используется PostgreSQL (тот же мажор, что прод — 16). Варианты: контейнер в CI или локально. Изоляция — транзакция-на-тест или пересоздание схемы. Выбор механики — за qa/devops (зафиксировать при настройке CI).

## Обязательные тест-кейсы (acceptance)

1. Ingest транскрибации возвращает `transcription_id` (и `summary_id` при переданном summary).
2. `POST /api/chat/messages` без `X-API-Key` → 401.
3. С неверным ключом → 401 (и не «протекает» через timing — проверяется логикой, не временем).
4. Пустая транскрибация / пустой message → 400.
5. transcription_id не существует → 404.
6. Успешный ответ (OpenAI замокан) → 201, поля `message_id`, `content`, `created_at`.
7. Списочная команда (`extract_tasks`/`checklist`/`decisions`/`risks_questions`) → присутствует `structured_blocks`.
8. Длинный текст > бюджета → применяется summary-first, ответ содержит пометку усечения; токены контекста ≤ бюджета.
9. Текст > бюджета даже после summary-first → 413 (too long context).
10. Таймаут OpenAI → 504; model error → 502.
11. История чата возвращается с пагинацией, в правильном порядке.
12. selected_text прокидывается в контекст.
13. **Детекция языка (unit, без LLM):** `detect_response_language` возвращает `ru` для кириллического `message`, `en` для английского, корректно обрабатывает короткие («Hi», «Да»), смешанные и неопределимые (цифры/emoji) строки; для неопределимого `message` применяется fallback (`transcription.language` → дефолт `ru`).
14. **Инъекция директивы языка (unit/integration, без реального LLM):** в собранном запросе к OpenAI последнее сообщение — `system` с директивой, требующей ответа на детектированном языке (правильный `{language_name}`); директива не усекается при summary-first.
15. **EN-вопрос по RU-контексту (integration, OpenAI замокан):** `message` на английском + транскрибация на русском → перехваченный запрос к OpenAI содержит директиву «Respond ONLY in English» последним сообщением.
16. **`translate_or_adapt`:** директива mirroring НЕ инжектируется (в `messages[]` отсутствует system-директива языка); целевой язык определяет команда.

## Coverage gate

- Минимум **80%** строк (`pytest --cov=app --cov-fail-under=80`). CI падает ниже порога.

## Запрещено в тестах

- Реальные вызовы OpenAI.
- Зависимость тестов от внешней сети.
- Хардкод секретов (использовать фикстуры/env override).
