# ADR-008 — Детерминированный language-mirroring: серверная детекция языка + явная директива (recency)

- Статус: Accepted
- Дата: 2026-06-10
- Supersedes: [ADR-007](ADR-007-system-prompt-language-mirroring.md)

## Context

[ADR-007](ADR-007-system-prompt-language-mirroring.md) добавил в системный prompt текстовое правило «отвечай на языке текущего сообщения пользователя». **На проде правило не сработало**: на английский вопрос по русской транскрибации модель отвечала по-русски.

Корневые причины:

1. **Правило конкурирует с доминирующим языком контекста.** Системный prompt написан на русском, транскрибация/summary/история — на русском; правило mirroring зарыто в середине русскоязычного блока в начале промта. Из-за recency-эффекта (модель сильнее учитывает конец контекста) и языкового перевеса контекста инструкция теряется.
2. **Подход непроверяем.** Юнит-тесты валидировали лишь наличие строки в константе prompt, а не фактическое поведение. Регрессия (ответ не на том языке) тестами не ловится.
3. **Опора на самоопределение модели недетерминирована** — то, что ADR-007 явно выбрал как «модель делает это надёжно сама», на практике оказалось неверным для коротких запросов на фоне иноязычного контекста.

ADR-007 в Alternatives отверг «детектировать язык на стороне backend и подставлять директиву динамически» ради простоты. Прод опроверг это допущение: простой вариант не работает. Настоящий ADR пересматривает решение.

## Decision

Language-mirroring становится **детерминированным и тестируемым**: язык целевого ответа вычисляется на сервере, и в контекст инжектируется **отдельная явная директива с конкретным целевым языком, размещённая последней (recency)**.

### 1. Серверное определение языка (гибрид: script-guard + lingua)

Новый модуль `app/core/language.py`, функция:

```
detect_response_language(message: str, transcription_language: str | None) -> str
```

Возвращает ISO 639-1 код языка (`"ru"`, `"en"`, и т. д.) целевого ответа. Первый аргумент — текущий пользовательский `message` (его язык определяют script-guard и lingua); второй, `transcription_language`, — язык транскрибации (`transcription.language` или `None`), используемый как fallback, когда `message` не несёт пригодного сигнала (нет буквенных символов / неопределимая письменность). См. п. 1.4.

Алгоритм (гибрид, детерминированный):

1. **Нормализация:** взять `message`, убрать ведущие/замыкающие пробелы. Для детекции учитывать только буквенные символы.
2. **Script-guard (быстрый и надёжный для коротких строк) — v1: кириллица + латиница.** Если среди буквенных символов есть символы кириллицы (диапазоны Unicode `U+0400–U+04FF`, `U+0500–U+052F`) и они составляют большинство буквенных символов — вернуть `"ru"` без обращения к библиотеке. Это снимает зависимость от вероятностной модели там, где script сам по себе детерминирует язык. **Любая иная не-латинская письменность (CJK, арабица и т. п.) в v1 НЕ маппится в ISO-код по script'у — она уходит в fallback (п. 1.4)** (доминирующая не-латиница либо отсутствие латиницы при не-доминирующей кириллице → fallback-цепочка). Расширение script-guard на дополнительные письменности — за рамками v1.
3. **Латиница → lingua.** Если доминирует латиница, вызвать `lingua` (детектор сконфигурирован на ограниченный набор языков — `English, Russian, German, French, Spanish, Italian, Portuguese`; набор расширяется по мере спроса, фиксируется в коде). lingua устойчив к коротким строкам, чем `langdetect`, и даёт `confidence`. Берётся язык с наибольшим confidence.
4. **Fallback (короткие / смешанные / неопределимые).**
   - Если после нормализации **нет буквенных символов** (только цифры/пунктуация/emoji) → fallback.
   - Если lingua вернул `None` (не смог определить) → fallback.
   - **Fallback-язык = `transcription.language`**, если он задан и валиден (ISO-код), иначе `DEFAULT_RESPONSE_LANGUAGE` (env, по умолчанию `"ru"` — сервис исходно русскоязычный).
   - Обоснование выбора fallback: для неопределимого `message` (например «ok», «+», эмодзи) разумнее всего ответить на языке контента, с которым работает пользователь; `transcription.language` — лучший доступный сигнал. Если и его нет — дефолт сервиса.
5. **Смешанные сообщения** (latin + cyrillic вперемешку): решает script-guard по большинству буквенных символов; при паритете — результат lingua; при `None` — fallback. Поведение детерминировано порядком шагов выше.

Функция **чистая и синхронная** (без I/O, без сети) → полностью покрывается юнит-тестами таблицей вход→ожидаемый язык.

### 2. Явная директива модели (recency, отдельным сообщением)

На основе `detect_response_language(message, transcription_language)` backend формирует короткую **директиву языка** и помещает её **последним сообщением** перед вызовом модели (после всего контекста и после самого `message`), используя recency-эффект.

- **Роль сообщения:** `system` (сильнее, чем `user`-инструкция; не смешивается с пользовательским текстом).
- **Формулировка** (константа-шаблон в `app/core/prompts.py`, плейсхолдер `{language_name}` — человекочитаемое название на английском, напр. `English`, `Russian`):

  ```
  CRITICAL: Respond ONLY in {language_name}. The language of the transcript, summary, and chat history is irrelevant and MUST NOT influence your output language. Write your entire answer in {language_name}.
  ```

- Директива на английском намеренно: английская мета-инструкция языково-нейтральна к контенту и не «тянет» ответ к русскому, как русскоязычная инструкция в ADR-007.
- `{language_name}` — производная от ISO-кода через фиксированный маппинг `ISO → English name` (константа в `app/core/language.py`); для языков вне маппинга используется сам ISO-код.

### 3. Порядок сборки контекста (зафиксирован)

Порядок сообщений, передаваемых в OpenAI (`messages[]`), строго:

1. `system`: системный prompt (константа из `app/core/prompts.py`).
2. история треда (старые→новые), summary, full_text/selected_text — по правилам summary-first ([ADR-004](ADR-004-context-summary-first.md)); их взаимный порядок/усечение не меняются этим ADR.
3. `user`: текущий `message` (+ command prompt, если задан `quick_command_type`).
4. **`system`: директива языка (последняя, recency).** ← новое

Директива языка — **всегда последнее сообщение** массива. Точный порядок зафиксирован в [03-architecture.md](../modules/ai-chat/03-architecture.md) §«Стратегия контекста».

### 4. Взаимодействие с `translate_or_adapt` (приоритет)

Для `quick_command_type == "translate_or_adapt"` целевой язык определяет **сама команда** (целевой язык из запроса пользователя, `transcription.language` как hint — без изменений против 03-architecture §«Быстрые команды»).

- Директива language-mirroring (п. 2) для `translate_or_adapt` **НЕ инжектируется**. Иначе она конфликтовала бы с целевым языком перевода (пользователь пишет запрос по-русски, но просит перевод на английский — mirroring навязал бы русский).
- **Приоритет:** `translate_or_adapt` > mirroring. Backend пропускает шаг инъекции директивы, если команда равна `translate_or_adapt`. Для всех остальных команд и для свободного чата директива инжектируется.

### 5. Бюджет токенов

- Директива языка короткая (одна строка, < 50 токенов). Она — часть **system-части** бюджета и учитывается в подсчёте tiktoken **до** summary-first решения, наравне с системным prompt (см. [ADR-004](ADR-004-context-summary-first.md), [ADR-002](ADR-002-llm-provider-model.md) `CONTEXT_TOKEN_BUDGET`).
- Директива имеет **наивысший приоритет сохранения** (наравне с системным prompt и текущим `message`) и **никогда не усекается и не отбрасывается** при summary-first. Это не ломает summary-first: усечению по-прежнему подлежат full_text/история/summary/selected_text в установленном порядке. Приоритет фиксируется в 03-architecture §«Стратегия контекста».

### 6. Текст системного prompt

Системный prompt (константа `app/core/prompts.py`) сохраняется как в ADR-007 **с одним изменением**: строка-правило mirroring внутри prompt остаётся (как мягкое дублирование), поскольку детерминизм теперь обеспечивает директива п. 2 и серверная детекция п. 1. Плейсхолдер отсутствующего значения (`не указано`/`not specified`) — без изменений; он следует целевому языку директивы. Менять текст prompt по-прежнему только через ADR.

## Consequences

- (+) Язык ответа детерминирован сервером, не зависит от вероятностного самоопределения модели на фоне иноязычного контекста — кейс «EN-вопрос по RU-контексту» решается.
- (+) Поведение **тестируемо без LLM**: детекция языка — чистая функция (unit-таблица), факт и содержимое инъекции директивы — проверяется на собранном `messages[]` (последнее сообщение = `system` с нужным `{language_name}`). См. [06-testing-strategy.md](../06-testing-strategy.md).
- (+) Recency-позиция директивы + английская мета-формулировка снимают конкуренцию с языком контекста.
- (+) Приоритет `translate_or_adapt` явно сохранён.
- (−) Новая runtime-зависимость `lingua-language-detector` (см. [02-tech-stack.md](../02-tech-stack.md)); инициализация детектора с набором языков имеет стоимость памяти/времени — детектор создаётся один раз (синглтон/lru) на процесс.
- (−) Детекция языка несовершенна на крайне коротких неоднозначных строках; покрыто детерминированным fallback (п. 1.4) и описано тестами edge-кейсов.
- (−) Незначительный рост токенов на одну короткую директиву на каждый запрос (учтён в бюджете, п. 5).

## Alternatives

- **Оставить только строку в prompt (ADR-007)** — отвергнуто: прод доказал нерабочесть и непроверяемость.
- **`langdetect`** — отвергнуто как основной детектор: ненадёжен на коротких строках (ровно наш кейс — короткий вопрос). lingua специально оптимизирован под короткие/смешанные тексты.
- **Только script-guard без библиотеки** — отвергнуто: не различает языки одной письменности (en/de/fr/es на латинице).
- **Просить модель самой определить и продублировать язык** — отвергнуто: остаётся недетерминированным и непроверяемым.
- **Fallback на `DEFAULT_RESPONSE_LANGUAGE` вместо `transcription.language`** — отвергнуто как первичный fallback: для неопределимого `message` язык контента (транскрибации) — более релевантный сигнал; дефолт сервиса используется только когда и язык транскрибации неизвестен.
