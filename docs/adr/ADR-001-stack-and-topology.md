# ADR-001 — Стек и топология: Python/FastAPI монолит + PostgreSQL в Docker

- Статус: Accepted
- Дата: 2026-06-09

## Context

Нужен маленький автономный backend-сервис AI-чата поверх транскрибаций. Развёртывание — VPS, Docker. Команда 1–2 человека. Пользователь зафиксировал стек: Python + FastAPI (Pydantic v2, Uvicorn) и PostgreSQL (отдельный контейнер). NFR — простота поддержки.

## Decision

- Язык/framework: **Python 3.12 + FastAPI** (Pydantic v2, Uvicorn) — по требованию пользователя.
- Доступ к БД: **SQLAlchemy 2 (async) + asyncpg**, миграции **Alembic**. Async выбран, т.к. главный путь — I/O-bound вызов OpenAI; async позволяет не блокировать воркер на время ответа модели.
- Хранилище: **PostgreSQL 16** в отдельном контейнере docker-compose.
- Топология: **монолит** (один сервис `api` + один `db`). Без очередей, кэша, брокеров.
- Корневой пакет приложения — `app/`.

## Consequences

- (+) Минимум движущихся частей, быстрый старт, простой деплой `docker compose up`.
- (+) Async-стек естественно ложится на ожидание OpenAI.
- (−) Отсутствие очереди означает, что долгие ответы LLM удерживают соединение (митигируется таймаутом 60 с, ADR-002).
- (−) Нет горизонтальной декомпозиции; для текущего масштаба не требуется.

## Alternatives

- **Flask/Django** — отвергнуто: пользователь зафиксировал FastAPI; FastAPI даёт нативную валидацию Pydantic v2 и async.
- **Микросервисы** — отвергнуто: избыточно для размера проекта, противоречит NFR простоты.
- **SQLite** — отвергнуто: пользователь зафиксировал PostgreSQL; нужна JSONB и многоконтейнерный деплой.
- **Sync SQLAlchemy** — отвергнуто: главный путь I/O-bound (OpenAI), async эффективнее.
