# ADR-004 — Стратегия контекста summary-first и оценка токенов tiktoken

- Статус: Accepted
- Дата: 2026-06-09

## Context

Транскрибации могут быть длиннее окна модели. Нужно гарантировать, что запрос к OpenAI помещается в бюджет, и при этом сохранять максимум релевантного контекста. ТЗ фиксирует стратегию summary-first и оценку токенов через tiktoken.

## Decision

Перед обращением к модели сервис формирует контекст в порядке приоритета и оценивает его токены через **tiktoken**:

1. Базовый случай (помещается в `CONTEXT_TOKEN_BUDGET`):
   `system_prompt + full_text + summary + selected_text + история текущего треда`.
2. Если оценка полного текста превышает бюджет → **summary-first**:
   `system_prompt + summary + selected_text + недавняя история` (full_text исключается). В ответ добавляется пометка, что использован сокращённый контекст (summary вместо полного текста).
3. Если и после summary-first контекст превышает бюджет → применяется **усечение** наименее приоритетных частей (сначала старая история, затем при необходимости усечение summary/selected_text) с пометкой усечения в ответе.
4. Если даже минимально необходимый контекст (system_prompt + усечённый selected_text/summary) не помещается → endpoint возвращает **413 (too long context)**.

Приоритет сохранения: system_prompt > текущий вопрос > selected_text > summary > full_text > история (от новой к старой).

Оценка токенов — `tiktoken` по энкодингу выбранной модели (fallback на `cl100k_base`/`o200k_base` при неизвестной модели).

## Consequences

- (+) Длинные транскрибации не приводят к ошибке окна модели в типовых случаях.
- (+) Прозрачность для пользователя: пометка усечения в ответе.
- (−) При summary-first ответы строятся по summary, точность по деталям полного текста снижается (ожидаемо). selected_text позволяет вернуть детальный фрагмент в контекст.
- (−) tiktoken-оценка приблизительна относительно реального токенайзера модели; берётся консервативный бюджет.

## Alternatives

- **RAG / эмбеддинги по чанкам** — отвергнуто для v1: усложняет стек (векторное хранилище), противоречит простоте. Может быть рассмотрено позже.
- **Жёсткое усечение по символам** — отвергнуто: неточно по токенам, риск переполнения окна.
