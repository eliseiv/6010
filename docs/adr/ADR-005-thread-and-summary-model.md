# ADR-005 — Один тред на транскрибацию; summary как отдельная сущность

- Статус: Accepted
- Дата: 2026-06-09

## Context

ТЗ требует сохранять историю чата по транскрибации (пользователь может вернуться к ответам) и различает `transcription_id` и `summary_id`. Нужно зафиксировать модель тредов и место summary.

## Decision

- **Один чат-тред на транскрибацию (v1).** История = все `chat_messages` с данным `transcription_id`, упорядоченные по `created_at`/`id`. Отдельной сущности «thread» нет — тред неявно задаётся `transcription_id`.
- **summary — отдельная таблица** `summaries(id, transcription_id, summary_text, created_at)`, связанная с транскрибацией. Причины:
  - ТЗ различает `transcription_id` и `summary_id` в контрактах.
  - У транскрибации может быть несколько summary (исходная при ingest и/или сгенерированная командой `make_summary`).
- При построении контекста используется: явно переданный `summary_id`, иначе — последняя по `created_at` summary транскрибации (если есть).
- `chat_messages.summary_id` — nullable FK, фиксирует, какая summary использовалась/подразумевалась для сообщения (для трассируемости).

## Consequences

- (+) Простая модель истории без лишней сущности thread.
- (+) Гибкость по summary: несколько версий, явная ссылка.
- (−) Невозможно вести несколько параллельных чатов по одной транскрибации в v1. Зафиксировано как [Q-AICHAT-1](../modules/ai-chat/99-open-questions.md) для будущего расширения (добавление `thread_id`).

## Alternatives

- **Явная сущность threads** — отвергнуто для v1: не требуется при «один тред на транскрибацию», добавляет сложность.
- **summary как колонка в transcriptions** — отвергнуто: не поддерживает несколько summary и отдельный `summary_id` из контракта.
