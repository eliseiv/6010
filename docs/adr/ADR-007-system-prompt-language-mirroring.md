# ADR-007 — Language-mirroring в системном prompt: ответ на языке сообщения пользователя

- Статус: Accepted
- Дата: 2026-06-10

## Context

Системный prompt (зафиксирован дословно в [03-architecture.md](../modules/ai-chat/03-architecture.md) §«Системный prompt») написан на русском языке и не содержит инструкции выбирать язык ответа. Из-за этого модель тяготеет к русскому независимо от языка запроса: пользователь, написавший сообщение на английском, получает ответ на русском. Жалоба поступила от iOS-разработчика, интегрирующего сервис.

Контекст запроса (транскрибация, summary, история) может быть на любом языке и не должен определять язык ответа: пользователь может задать вопрос на английском по русской транскрибации и ожидает английский ответ.

Системный prompt помечен «менять только через ADR», поэтому изменение оформляется отдельным решением.

## Decision

В дословно зафиксированный системный prompt добавляется правило **language-mirroring**: агент отвечает на том же языке, на котором написано текущее сообщение пользователя (`message`). Язык контекста (транскрибация/summary/история) на язык ответа не влияет.

Зафиксированы нюансы приоритета и формулировок:

1. **Приоритет языка ответа:**
   - По умолчанию язык ответа = язык текущего `message`.
   - Исключение — команда `translate_or_adapt`: для неё целевой язык определяется самой командой и её целевым/исходным языком (из `message`, с `transcription.language` как hint, см. [03-architecture.md](../modules/ai-chat/03-architecture.md) §«Быстрые команды»). Правило mirroring для этой команды не применяется и ей не противоречит.

2. **Плейсхолдер отсутствующего значения следует языку ответа.** Маркер `не указано` (из ТЗ, для пустых владельца/срока и т. п.) даётся на языке ответа: `не указано` для русского ответа, `not specified` для английского, аналогично для других языков.

Все остальные правила prompt сохраняются без изменений: grounding (работать только с предоставленным контекстом, не выдумывать факты, говорить если ответа нет в транскрибации), краткость и структурность, формат списков задач (действие/владелец/срок), привязка к исходной транскрибации.

### Итоговый дословный системный prompt

```
Ты AI-ассистент внутри приложения для транскрибации. Работай только с контекстом текущей транскрибации, summary и выбранными пользователем фрагментами. Не выдумывай факты вне предоставленного текста. Если ответа нет в транскрибации, так и скажи и предложи, какой дополнительный контекст нужен.
Отвечай на том же языке, на котором написано текущее сообщение пользователя. Язык транскрибации, summary и истории на язык ответа не влияет — даже если контекст на другом языке, отвечай на языке текущего вопроса. Исключение: для команды перевода/адаптации язык результата определяется самой командой (целевой язык из запроса пользователя).
Твоя задача — помогать пользователю извлекать пользу из транскрибации: делать summary, выделять action items, решения, риски, открытые вопросы, планы, follow-up сообщения, чек-листы и структурированные заметки.
Отвечай кратко и структурно. Если пользователь просит список задач, возвращай пункты с понятным действием, владельцем и сроком, если они есть в тексте. Если владельца или срока нет, помечай это на языке твоего ответа (`не указано` для русского, `not specified` для английского и т. п.).
Всегда сохраняй привязку к исходной транскрибации и не уходи в общие советы, если пользователь прямо не просит этого.
```

## Consequences

- (+) Ответ соответствует языку запроса пользователя; устранена жалоба интеграторов.
- (+) Поведение явно и однозначно зафиксировано в дословном prompt — backend реализует константу 1:1.
- (+) Нет конфликта с `translate_or_adapt`: приоритет языка для неё явно отдан команде.
- (−) Маркер отсутствующего значения теперь зависит от языка ответа — backend, если делает строковый матчинг `не указано` для построения `structured_blocks`, должен опираться на машинное поле (`owner=null`/`due=null`), а не на текст маркера. Это уже так по контракту (02-api-contracts §structured_blocks: источник истины — `null`-поля, markdown — производная).
- (−) Системный prompt стал длиннее на несколько строк (незначительный рост токенов system части бюджета, см. ADR-004).

## Alternatives

- **Определять язык ответа по транскрибации/`transcription.language`** — отвергнуто: ломает кейс «вопрос на одном языке по контексту на другом», именно он и вызвал жалобу.
- **Принудительно отвечать всегда на английском** — отвергнуто: сервис исходно русскоязычный, многие пользователи пишут по-русски.
- **Детектировать язык на стороне backend и подставлять директиву в prompt динамически** — отвергнуто для v1: усложняет код и дублирует то, что модель делает надёжно сама; правило в системном prompt проще и достаточно.
