# 00 — Vision

## Цель

Предоставить маленький автономный backend-сервис, который позволяет вести AI-чат поверх ранее загруженных транскрибаций. LLM (OpenAI) отвечает строго в рамках контекста конкретной транскрибации: полный текст, summary, выбранный пользователем фрагмент, история текущего чата. Сервис хранит транскрибации, summary и историю чатов в собственной PostgreSQL.

## Пользовательские сценарии

1. Внешняя система загружает транскрибацию (и опционально summary) → получает `transcription_id`.
2. Пользователь задаёт вопрос по транскрибации → получает markdown-ответ от LLM.
3. Пользователь запускает быструю команду (extract_tasks, make_summary, …) → получает структурированный результат (markdown + опционально structured_blocks).
4. Пользователь выделяет фрагмент текста и задаёт по нему вопрос (selected_text).
5. Пользователь возвращается к транскрибации позже и читает историю чата.

## Scope (v1)

- Ingest транскрибаций и summary.
- Один чат-тред на транскрибацию.
- Главный endpoint создания сообщения с обращением к OpenAI.
- 10 быстрых команд (enum `quick_command_type`).
- Системный prompt, ограничивающий агента контекстом транскрибации.
- summary-first стратегия обрезки контекста для длинных текстов (оценка токенов через tiktoken).
- structured_blocks для списочных команд.
- История чата с пагинацией.
- Аутентификация по `X-API-Key`.
- Обработка ошибок: timeout, model error, empty transcription, too long context.

## Out of scope (v1)

- Множественные треды на одну транскрибацию (один тред на транскрибацию — см. Q-AICHAT-1).
- Многопользовательский доступ / разграничение прав между пользователями (единый API_KEY на сервис).
- Streaming-ответы (SSE/WebSocket).
- Загрузка аудио и сама транскрибация (текст приходит готовым).
- Rate limiting на пользователя (см. TD-002).
- UI / frontend.
- Векторный поиск / RAG-эмбеддинги (контекст передаётся целиком или через summary-first усечение).

## Нефункциональные требования (NFR)

| NFR | Требование |
|---|---|
| Простота | Монолит, минимум зависимостей. Один сервис + одна БД. Критерий выбора решений — простота поддержки командой 1–2 человек. |
| Безопасность | Все секреты только из `.env`. Constant-time сравнение API-ключа. Секреты не в Docker-образе. |
| Надёжность | Корректная обработка ошибок LLM (timeout, model error) с понятными HTTP-кодами, без 500 «наружу» где можно дать осмысленный ответ. |
| Переносимость | Развёртывание в Docker на VPS через docker-compose. |
| Производительность | Latency главного endpoint определяется OpenAI; целевой таймаут к OpenAI — 60 с (см. ADR-002). |
| Наблюдаемость | Структурное логирование запросов/ошибок; `/health` без ключа. |

## Критерии успеха

- Можно загрузить транскрибацию и получить осмысленный ответ от агента строго по её содержанию.
- Быстрые команды возвращают корректный markdown + structured_blocks где предусмотрено.
- Длинные транскрибации не приводят к ошибке «too long context» благодаря summary-first.
- Сервис разворачивается одной командой `docker compose up`.
